# Инструкция для помощника, который правит этот сайт

Прочитайте эту страницу целиком, прежде чем менять файлы. Она короткая.

## Что это

Личный дневник Данила Сарыкова, https://www.sarykov.ru. Статический сайт на
GitHub Pages: сервера нет, базы нет. Записи приезжают из Telegram-канала сами,
раз в 15 минут, отдельной сборкой.

Исходники открыты, лицензия MIT (файл `LICENSE`). Код можно менять свободно;
тексты, фотографии и видео дневника — личные материалы автора, лицензия на них
не распространяется.

## Где код

**Весь сайт — один файл `index.html`.** В нём три части, каждая подписана
комментарием заглавными буквами:

| | Часть | Где |
|---|---|---|
| 1 | **СТИЛИ** — цвета, шрифты, вся внешность | `<style>` в шапке, начинается с блока `ТОКЕНЫ` |
| 2 | **РАЗМЕТКА** — шапка и пять разделов | `<body>` |
| 3 | **СКРИПТ** — вкладки, лента, плеер, часы | в самом низу, перед `</body>` |

Отдельного файла со скриптом нет — не ищите `assets/js/site.js`, его удалили
намеренно. Карта со списком блоков продублирована комментарием в первых
строках `index.html`, подробная — в `README.md`.

Остальное трогать обычно не нужно: `sw.js` (кэш и работа без сети),
`scripts/` (сборка записей из Telegram).

## Как опубликовать

```sh
git pull                       # обязательно: над сайтом работает не один помощник
# ... правки в index.html ...
node scripts/check-site.mjs    # проверка, пишет по-русски, что не так
git add -A && git commit -m "что сделано"
git push origin main
```

Ветка `main` — рабочая. Через минуту после push GitHub Pages выкладывает
изменения на https://www.sarykov.ru сам, ничего дополнительно делать не нужно.

`node scripts/check-site.mjs` **запускайте перед каждым push.** Он ловит то,
что уже ломалось: ссылку на чужой сервер, путь к несуществующему файлу,
опечатку в скрипте, случайно снесённый раздел. Та же проверка идёт на GitHub
после отправки — если она красная, сайт у читателей уже сломан, чините сразу.

## Чего делать нельзя

1. **Никаких ссылок на чужие серверы** — ни `cdn.plyr.io`, ни
   `fonts.googleapis.com`, ни любых других. У части читателей эти домены
   недоступны, и страница встаёт колом. Всё нужное уже лежит в репозитории.
   И не выдумывайте значения `integrity`: с неверным хэшем браузер не
   загрузит файл нигде и никогда.
2. **Плеер свой, библиотеку сюда не тянуть.** Plyr уже пробовали и убрали:
   32 КБ, чужое оформление поверх нашего и свои поломки. У нашего плеера есть
   всё — перемотка, скорость, качество, полный экран, кружочки, клавиши,
   жесты. Каждая его особенность закрывает поломку, которая тут случалась;
   список — в `README.md`.
3. **Не разносить сайт обратно по файлам.** Один файл — сознательное решение,
   на скорость загрузки это не влияет (замерено).
4. **Не удалять то, чего не понимаете.** Однажды при переделке плеера снесли
   окно просмотра целиком — вместе с перемоткой, выбором качества и кружочками.
   Если функция кажется лишней, сначала спросите.
5. **Не править то, что генерируется:** `data/posts.json`, `assets/posts/`,
   `assets/fonts/`. Робот перезапишет.
6. **Не откатывать ускорения.** `media="print"` у шрифтов, `sw.js`, отсутствие
   `<video>` в ленте — каждое куплено замером на канале 400 кбит/с. Полный
   список с числами — в `README.md`, раздел «Что нельзя ломать».

## Если работаете не один

Сначала `git pull`, в конце сразу `git push`. Дважды уже выходило так, что
двое переписывали одно и то же место одновременно, и вторая работа ложилась
поверх первой. Если функции нет там, где вы её ждёте, — посмотрите свежий
`index.html`, а не считайте, что код потерялся.
