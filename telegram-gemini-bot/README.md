# Telegram-бот: посты через Grok

Бот превращает текст, фото, видео, кружочки (video_note) и голосовые
сообщения в готовые посты с помощью xAI Grok, а также умеет
публиковать, редактировать и удалять посты в вашем Telegram-канале.

## Вариант A: запуск через GitHub Actions (без своего сервера)

Не нужен свой компьютер или сервер — бот опрашивается прямо на серверах
GitHub по расписанию (workflow `.github/workflows/telegram-gemini-bot.yml`;
имя файла осталось прежним, чтобы не переписывать самозапуск в
`poll_once.py` — см. «Архитектурные решения» ниже).

**Как это работает:** `poll_once.py` опрашивает Telegram до пяти минут,
обрабатывает сообщения и после успешного цикла сам стартует следующий запуск.
Расписание раз в 30 минут — только резерв, если цепочка прервалась. Обычно бот отвечает
в текущем или следующем цикле, но бесплатные раннеры GitHub могут добавить задержку.

### Настройка

1. Открой репозиторий на GitHub → **Settings → Secrets and variables →
   Actions → New repository secret** и добавь четыре секрета:
   - `TELEGRAM_BOT_TOKEN`
   - `XAI_API_KEY`
   - `CHANNEL_ID`
   - `ADMIN_ID`
2. Убедись, что бот добавлен в канал администратором с правами
   публикации/редактирования/удаления сообщений.
3. Workflow сам продолжает цепочку запусков, а расписание (`cron: '*/30 * * * *'`)
   служит резервом.
   Можно также запустить его вручную: вкладка **Actions** → **Telegram
   Grok bot** → **Run workflow**.
4. Логи каждого запуска смотри там же, во вкладке **Actions** — там видно,
   сколько сообщений обработано и нет ли ошибок (например, неверный ключ
   xAI или у бота нет прав в канале).

### Важные ограничения

- **Задержка ответа** — обычно до нескольких минут; GitHub может позже выдать
  бесплатный раннер.
- **Автоотключение расписания** — если в репозиторий 60 дней не было
  коммитов, GitHub сам отключает `schedule`-триггер. Тогда нужно один раз
  запустить workflow вручную (Run workflow) или сделать любой коммit —
  расписание снова заработает.
- Секреты в GitHub Actions не попадают в публичные логи (GitHub маскирует
  их значения), но всё равно не публикуй их и не коммить `.env` в репозиторий.
- Сообщения и файлы, отправленные боту, передаются в xAI (Grok). Не посылай
  секреты и персональные данные других людей без их согласия.

## Вариант B: запуск на своём компьютере/сервере

Ниже — классический способ, если хочется бота без задержек, работающего
постоянно через `bot.infinity_polling()`.

### 1. Установка

```bash
python -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

Для обычного видео (не кружочков и не голосовых) дополнительно нужен
`ffmpeg` в `PATH` — им достаются кадры для Grok Vision. Без него видео
всё равно обработается, но только по звуку (см. «Как это устроено внутри»).

### 2. Настройка

1. Скопируйте `.env.example` в `.env`:
   ```bash
   cp .env.example .env
   ```
2. Заполните значения:
   - `TELEGRAM_BOT_TOKEN` — получите у [@BotFather](https://t.me/BotFather).
   - `XAI_API_KEY` — получите на https://console.x.ai.
   - `CHANNEL_ID` — id канала (например, `-1001234567890`) или его
     `@username`. **Бот должен быть добавлен в канал как администратор**
     с правом публикации/редактирования/удаления сообщений.
   - `ADMIN_ID` — обязательный числовой ID вашего личного Telegram-аккаунта. Все
     команды, тексты и медиа бот принимает только от этого ID.
     Узнать свой id можно у [@userinfobot](https://t.me/userinfobot).

### 3. Запуск

```bash
python bot.py
```

## Как пользоваться

- Отправьте боту **текст** — он вернёт красиво оформленный пост.
- Отправьте **фото** — бот распознает содержимое через Grok Vision и
  предложит пост.
- Отправьте **видео** — бот вытащит несколько кадров и расшифрует звук,
  предложит пост по тому и другому вместе (см. ограничение ниже).
- Отправьте **кружочек** (video_note) или **голосовое** (voice) — бот
  расшифрует речь через Grok Speech-to-Text и превратит её в пост.
- `/post <текст>` — опубликовать текст в канал (вернёт ID сообщения).
- `/edit <ID> <новый текст>` — изменить опубликованный пост по ID.
- `/delete <ID>` — удалить пост по ID.

## Как это устроено внутри

- **Текст** — обычный запрос в `xai_client.chat.completions.create(...)`,
  модель `GROK_TEXT_MODEL` (умолчание `grok-4`).
- **Фото** — картинка кодируется в data URL (`data:image/jpeg;base64,...`)
  и уходит одним сообщением в `GROK_VISION_MODEL` (умолчание
  `grok-2-vision-latest`). Отдельной загрузки файла, в отличие от бывшего
  Gemini File API, не нужно — Grok принимает картинку прямо в теле запроса.
- **Голосовое и кружочек** — файл целиком уходит в Grok Speech-to-Text
  (`POST /v1/stt`), результат (поле `text` в ответе) подставляется в текстовый
  промпт и уходит в `GROK_TEXT_MODEL`.
- **Обычное видео** — у Grok, в отличие от Gemini, нет API, понимающего видео
  целиком одним запросом. Вместо этого `extract_video_frames()` вытаскивает
  ffmpeg'ом несколько кадров, равномерно распределённых по длине ролика,
  `transcribe_with_grok()` отдельно расшифровывает звук, и всё это разом
  уходит в `GROK_VISION_MODEL`. **Это приближение, не настоящий просмотр**:
  то, что произошло между кадрами и без звука, в пост не попадёт. Если
  `ffmpeg`/`ffprobe` не установлены или файл без звука — бот всё равно
  постарается сделать пост по тому, что есть (только кадры или только звук),
  и упадёт с понятной ошибкой, только если не осталось вообще ничего.

## Заметки

- Файлы больше 20 МБ отклоняются, а ожидание ответа Grok (текст, картинка,
  расшифровка) ограничено `GROK_FILE_TIMEOUT_SECONDS` (умолчание 120 секунд).
- Скачанные из Telegram и промежуточные (кадры видео) временные файлы
  удаляются локально сразу после обработки.
- Имена моделей xAI меняются заметно чаще, чем у Gemini: если бот вдруг
  начнёт отвечать `404`/`model not found`, в первую очередь проверьте
  `GROK_TEXT_MODEL`/`GROK_VISION_MODEL` в переменных окружения (можно
  переопределить, не трогая код — см. `.env.example`).

## История отладки и грабли (для того, кто продолжит работу над ботом)

Этот раздел — конспект всего, на что реально наткнулись при первом запуске
бота и при переходе с Gemini на Grok, чтобы не проходить это заново. Если
бот вдруг перестанет отвечать — начните отсюда, вероятная причина почти
наверняка уже здесь описана.

### Архитектурные решения и почему

- **Бот живёт на GitHub Actions, не на сервере.** `bot.py` содержит все
  обработчики и поддерживает классический `bot.infinity_polling()` для
  локального запуска, но в проде используется `poll_once.py` — он
  импортирует обработчики из `bot.py` и опрашивает Telegram короткими
  сессиями (`POLL_SECONDS`, сейчас 300 сек), укладываясь в лимит одного
  запуска Actions. Это осознанный компромисс: бесплатно и без сервера,
  но с задержкой ответа.
- **Файл и папка остались `telegram-gemini-bot`/`telegram-gemini-bot.yml`
  после перехода на Grok.** Переименование задело бы `poll_once.py` (URL
  самозапуска собирается по имени файла workflow), `dependabot.yml` и
  `proverka.yml` (оба указывают на папку) — цена переименования ради
  одного только имени показалась выше пользы. Отображаемое имя workflow
  в интерфейсе Actions при этом обновлено на «Telegram Grok bot».
- **`openai`, а не отдельный SDK от xAI.** У xAI обычный OpenAI-совместимый
  `/chat/completions`, официальный Python SDK не публиковали отдельно —
  проще и надёжнее взять готовый клиент `openai` с `base_url=
  "https://api.x.ai/v1"`, чем писать свой поверх `requests`.
- **Speech-to-Text — отдельный `requests.post`, не через `openai`-клиент.**
  `/v1/stt` — свой эндпоинт xAI, не часть стандартного Chat Completions API,
  которое понимает пакет `openai`. Обычный multipart-запрос с файлом.
- **Видео — кадры + звук, а не один запрос.** См. «Как это устроено
  внутри» выше. Решение принято из-за того, что публичный API Grok на
  момент написания не документировал приём видеофайла целиком в
  Chat Completions (в отличие от Gemini File API, который явно на это
  рассчитан). Если xAI позже добавит такую возможность официально —
  `ask_grok_about_video()` можно упростить до одного запроса.
- **`CHANNEL_ID` — числовой ID, а не `@username`.** `@username` у канала
  срабатывает, только если у канала реально есть публичный username и
  бот в нём администратор. Надёжнее — числовой ID вида `-1001234567890`.
  Способ его узнать: переслать (forward) любой пост из канала в личку
  боту — `handle_text` в `bot.py` ловит `message.forward_from_chat` и
  отвечает точным ID/username, не уходя в Grok.
- **Бот должен быть админом канала** с правами "Публикация/Редактирование/
  Удаление сообщений", иначе `/post`, `/edit`, `/delete` падают с той же
  ошибкой `Bad Request: chat not found`, что и при неверном `CHANNEL_ID`
  — при отладке проверяйте оба варианта, ошибка одна и та же для обеих
  причин.
- **`timeout-minutes` в workflow должен быть заметно больше, чем
  `POLL_SECONDS`.** Изначально было `timeout-minutes: 5` при
  `POLL_SECONDS: 260` — впритык, и один запуск не уложился (GitHub убил
  job по таймауту, `conclusion: cancelled`, сообщение осталось
  необработанным). Сейчас `timeout-minutes: 12` / `POLL_SECONDS: 300`: этого
  хватает и на установку зависимостей, и на обработку сообщения, пришедшего
  под конец опроса. Ожидание ответа Grok ограничено отдельно
  `GROK_FILE_TIMEOUT_SECONDS` (120 секунд).
- **`concurrency: cancel-in-progress: false`** — новый запуск не отменяет тот, который ещё
  опрашивает Telegram. Он ждёт в очереди, поэтому цепочка больше не отменяет сама себя.
- **Расписание `*/30 * * * *` — резерв, а не точный таймер.**
  Наблюдались разрывы от 2 минут до больше часа — это поведение самого
  GitHub, не что-то, что можно починить в коде. Если нужен более
  быстрый ответ прямо сейчас — вкладка **Actions → Telegram Grok bot
  → Run workflow** запускает бота немедленно.
- **`permissions: contents: read`** у workflow — бот никогда не
  коммитит в репозиторий, только ходит во внешние API, так что права на
  запись ему не нужны (принцип минимальных привилегий).

### Где искать актуальные значения секретов

Секреты (`TELEGRAM_BOT_TOKEN`, `XAI_API_KEY`, `CHANNEL_ID`,
`ADMIN_ID`) задаются только в **Settings → Secrets and variables → Actions**.
GitHub не показывает их значения после сохранения. Не храните копии токенов в обычных файлах;
если копия утекла (например, случайно попала в переписку, коммит или чат) —
перевыпустите токен/ключ и обновите Secret, не полагаясь на то, что старое
значение никто не увидел.

### Как быстро продиагностировать проблему

1. Вкладка **Actions** репозитория → workflow **Telegram Grok bot** →
   смотрите последние запуски и их `conclusion` (success/failure/cancelled).
2. `failure` — открыть запуск, посмотреть, на каком шаге упал, и текст
   ошибки в логе шага "Опросить Telegram и обработать сообщения".
3. `cancelled` — это больше не штатная часть цепочки. Проверьте таймаут, ручную отмену
   и логи предыдущих шагов.
4. Бот отвечает ошибкой в самой переписке (например,
   "❌ Ошибка запроса к Grok: ...") — текст ошибки обычно
   самодостаточен, он приходит прямо от xAI/Telegram API.
