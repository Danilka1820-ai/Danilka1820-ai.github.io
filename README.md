# sarykov.ru — дневник Данила Сарыкова

Статический сайт на GitHub Pages. Записи приезжают из Telegram-канала
[@danilka2028k](https://t.me/danilka2028k) сами, каждые 15 минут.

Эта страница — карта для того, кто правит код: где что лежит, что можно менять
свободно, а что сломает сайт у читателей на слабом интернете.

---

**Если над сайтом работает несколько помощников.** Перед правкой — `git pull`,
после — сразу коммит и push. Дважды уже выходило так, что двое переписывали
плеер одновременно и вторая работа ложилась поверх первой. И проверяйте по
названиям функций в этом файле: если функции нет — сначала посмотрите свежий
`assets/js/site.js`, а не считайте, что код потерялся.

**Перед правкой обязательно прочитайте раздел «Что нельзя ломать» ниже.**
Там не вкусовщина, а вещи, каждая из которых уже проверена замерами: если их
откатить, сайт снова начнёт открываться по тринадцать секунд.

Файлы, которые править бесполезно — их перезаписывает робот:
`data/posts.json`, `assets/posts/`, `assets/fonts/`.

## Как всё устроено

```
Telegram-канал
      │  каждые 15 минут, .github/workflows/telegram-sync.yml
      ▼
scripts/fetch-telegram-posts.mjs
      │  читает публичную превью-страницу t.me/s/danilka2028k
      │  тексты  → data/posts.json
      │  медиа   → assets/posts/  (сжимает и переводит в H.264)
      ▼
index.html — читает data/posts.json в браузере и рисует ленту
```

Сервера нет, базы нет, бота нет. Всё, что видит читатель, лежит в этом
репозитории — поэтому сайт открывается и там, где Telegram заблокирован.

## Где что внутри `index.html`

Файл один, но разделён заголовками-комментариями. Ищите по ним.

**Стили** (`<style>`, примерно строки 46–534):

| Блок | За что отвечает |
|---|---|
| `ТОКЕНЫ` | цвета, шрифты, отступы. **Меняя дизайн, начинайте отсюда** |
| `ШАПКА` | имя, разделы и часы в одну строку |
| `РАЗДЕЛЫ` | переключение вкладок |
| `ГЕРОЙ`, `ТЕЗИС` | первый экран главной |
| `ЛЕНТА` | рельс с датами, карточка записи, фильтры |
| `─── Кадр в ленте ───` | постер с кнопкой пуска, фото, кружочки |
| `─── Окно просмотра ───` | окно поверх страницы и подгонка Plyr под сайт |
| `─── Полный экран ───` | поведение при развороте на весь экран |
| `О ДНЕВНИКЕ`, `ВОПРОСЫ`, `КОНТАКТЫ И ПОДВАЛ` | остальные разделы |
| `ПОЯВЛЕНИЕ` | анимации при прокрутке |
| `МОБИЛЬНЫЕ` | правки под узкие экраны |

Вся палитра и ритм заданы переменными в `:root`. Смена настроения сайта — это
правка десятка значений там, а не переписывание стилей.

**Разметка** (`<body>`): пять панелей — `#tab-home`, `#tab-diary`, `#tab-about`,
`#tab-faq`, `#tab-contacts`. Каждая помечена комментарием вида `═══ ГЛАВНАЯ ═══`.

**Скрипт** — отдельный файл `assets/js/site.js`. В начале файла лежит
содержание с семью разделами, искать по их названиям.

| Функция | Что делает |
|---|---|
| `showTab` / `tabByHash` | вкладки и адреса вида `#/dnevnik` |
| `movePill` | переезжающая капсула в шапке |
| `loadOnce` | подгружает Plyr при первом открытии ролика |
| `startPlayer` | создаёт плеер: русские подписи, качество, скорость |
| `showInTheater` | показывает ролик номер N: источники, пропорции, подпись |
| `bestHeight` | выбирает качество под экран |
| `openTheater` / `closeTheater` / `step` | открыть, закрыть, соседний ролик |
| `buildEntry` | собирает одну карточку записи |
| `renderInto` | рисует ленту, возвращает список тем |
| `renderFilters` | кнопки рубрик |
| `splitTitle` | берёт первую строку записи как заголовок |
| `partsFromDate` | дата и день недели для рельса |

**В ленте плеера нет** — только кадр с кнопкой (`buildPoster`, классы `pl__*`).
Это обычная картинка-постер: ни одного элемента `<video>` на странице, ни байта
ролика по сети до нажатия.

**Всё управление — в окне просмотра** (`openTheater`, классы `tv__*`). Нажатие
на кадр открывает его: крупный кадр, дорожка с перемоткой, скорость, громкость,
качество, полный экран, стрелки к соседним роликам.

**Плеер — сторонний, Plyr 3.8.4** (MIT), и он лежит у нас:
`assets/vendor/plyr/`. Файлы с чужих серверов не подключаются — ни `cdn.plyr.io`,
ни какой-либо другой: там, где интернет режут, страница не должна ничего ждать.
Библиотека подгружается только при первом нажатии на ролик (`loadOnce`), это
32 КБ вместе со стилями; кто видео не смотрит, за неё не платит. Обновлять —
заменой файлов в этой папке, ссылки в разметке не нужны.

Три места, где библиотеку пришлось поправить снаружи — не трогайте, не
разобравшись:

* пропорции кадра задаются через `player.config.ratio` **до** назначения
  источника. Свойство `player.ratio` в этой версии теряет переданное значение,
  и кадр остаётся 300×150, пока не прочитается файл;
* при закрытии окна снимаются общедокументные обработчики клавиш
  (`globalKeys(false)`), иначе пробел запускает невидимый ролик;
* на узком экране дорожка переносится на свою строку, а в кружочке панель
  обрезана до того, что помещается по хорде круга.

**Два качества, версия выбирается сама.** Сборщик делает к каждому ролику
вторую, лёгкую версию (`-low.mp4`) и пишет в данные размер кадра и вес обоих
файлов. `bestHeight` считает, сколько настоящих точек займёт кадр (геометрия
окна, а не текущая разметка — в момент выбора кадр ещё не разложен), плотность
экрана ограничивает двойкой и берёт лёгкую версию, если та покрывает четыре
пятых нужного. На телефоне это лёгкая, на мониторе — полная. Вручную качество
меняется в настройках плеера (шестерёнка); при 2G и экономии трафика всегда
лёгкая.

Выше исходника подняться нельзя: Telegram отдаёт кружочки 512×512, видео
1280×720. Поэтому кадр не растягивается больше чем в 1,6 раза от размера файла
(`--tv-cap`) — детали от этого не прибавится, а мыла прибавится. Если лёгкая версия не вышла
легче на 15 процентов, она не сохраняется, и выбора в настройках не будет.

**Полный экран** держит на себе библиотека, включая обходной путь для iPhone,
где система разворачивает только сам видеоэлемент. Нам остаётся кружочек: в
полном экране он должен остаться кругом и не раздуться выше настоящего размера
файла — за это отвечает блок `─── Полный экран ───` в стилях.

Окно одно на всю страницу, у него один плеер — меняется только источник.
Клавиши: пробел — пуск, ← → — перемотка, N и P — соседний ролик, Esc — закрыть.

Второй набор кнопок прямо в ленте был убран сознательно: он повторял окно и
стоил около 170 строк кода и четырнадцати элементов `<video>` на странице.

## Что нельзя ломать

Это не вкусовщина — каждый пункт куплен замерами на канале 400 кбит/с,
то есть на том интернете, который есть у части читателей.

**1. Шрифты только свои, из `assets/fonts/`.**
Не возвращайте `<link>` на `fonts.googleapis.com`. Пока внешний сервер молчит,
страница стоит белой: замер показал **13,4 секунды до появления текста против
1,3 секунды со своими шрифтами**. В регионах этот домен режут.
Описания `@font-face` встроены прямо в `index.html` между метками
`/* ШРИФТЫ:НАЧАЛО */` и `/* ШРИФТЫ:КОНЕЦ */` — отдельный файл стоил бы лишнего
обращения к серверу. **Руками между метками не писать**: блок перезаписывает
`node scripts/vendor-fonts.mjs`, он же кладёт woff2 и обновляет `fonts.css`.

**1г. Плеер тоже свой, из `assets/vendor/plyr/`.**
То же правило, что и со шрифтами: `cdn.plyr.io` и любые другие чужие адреса в
разметке недопустимы. Их режут там же, где Google, а подпись `integrity` с
неверным хэшем блокирует файл вообще везде. Обновление библиотеки — это замена
файлов в папке, а не ссылка на CDN. Заглушку `blank.mp4` (её просит сама
библиотека) при необходимости создаёт шаг «Заглушка для плеера» в
`.github/workflows/telegram-sync.yml`.

**1в. Шрифты подключаются после ленты.**
Блок `<style id="fontStyles" media="print">` не даёт браузеру качать 174 КБ
начертаний, пока не приедут записи; `site.js` переключает `media` на `all`
сразу после отрисовки. Замер: первая запись появляется через **3,8 секунды
вместо 7,4**. Не убирайте `media="print"` и вызовы `enableFonts()`.

**1а. Служебный работник `sw.js` — не удалять.**
Благодаря ему повторный заход не тратит **ни одного байта**, а при полном
обрыве сети сайт всё равно открывается со всеми записями. Страницу и
`posts.json` он берёт из сети (кэш только на случай обрыва), статику — из кэша,
видео не трогает вовсе. Меняете список файлов — поднимите `CACHE` на новую
версию, иначе у читателей останется старый кэш.

**1б. Экономный режим.**
При 2G или включённой экономии трафика на `<html>` вешается класс `thin`:
отключаются фоновая подсветка, размытия и постеры к видео. Проверять — в
DevTools через Network throttling и `navigator.connection`.

**2. У видео `preload="none"`.**
С `metadata` браузер лезет в файлы сам, и открытие страницы стоит мегабайтов.
Сейчас при загрузке скачивается **ноль байт видео** — ролик идёт по сети только
после нажатия.

**3. Медиа не трогать руками.**
`assets/posts/` и `data/posts.json` перезаписывает робот. Любая ручная правка
пропадёт при следующей синхронизации.

**4. Пять разделов остаются разделами.**
Вкладки `Главная · Записи · О дневнике · Вопросы · Контакты` в одну строку с
именем — это просьба владельца сайта. Не сводите их обратно к одной длинной
странице.

**5. Экраны — от 320 пикселей до телевизора.**
Проверено на ширинах 320, 360, 390, 430, 768, 1024, 1280, 1440, 1920, 2560 и
3840. Выше 1600 пикселей растут и полоса, и кегль, и рельс: на телевизоре,
который смотрят с трёх метров, колонка в 1160 пикселей с текстом 19 пикселей
нечитаема. Горизонтальной прокрутки не должно быть нигде.

**6. Пульт и клавиатура.**
На телевизорах и приставках курсора нет — ходят стрелками. Рамка выбора
(`:focus-visible`) обязана быть заметной, а `scroll-margin-top` не даёт липкой
шапке накрыть выбранный элемент. Мелкие ссылки расширены невидимой подложкой
до размера, в который попадают пальцем и пультом, — не убирайте `::after`
у `.entry__more` и `.foot a.u`.

**7. Читается без Telegram.**
Тексты, фото и видео обязаны лежать на самом сайте. Ссылка «Оригинал» — это
дополнение, а не способ доставки.

## Как проверять правки

Сборки нет, открывается как есть:

```bash
python3 -m http.server 8000    # затем http://localhost:8000
```

Перед публикацией стоит проверить:

- открываются все пять разделов, в том числе по прямой ссылке (`/#/dnevnik`);
- в ленте есть записи, фильтры переключаются;
- кружочек играет по нажатию и встаёт на паузу повторным;
- на ширине 390 пикселей нет горизонтальной прокрутки;
- в консоли пусто;
- при загрузке страницы не качается ни одного `.mp4`.

Сборщик можно погонять и вручную — но помните, что он перезапишет `data/`
и `assets/posts/`:

```bash
node scripts/fetch-telegram-posts.mjs
```

Без `ffmpeg` он отработает, но молча пропустит сжатие: в логе будет строка
`Обработка медиа: ffmpeg НЕТ`. В GitHub Actions ffmpeg ставится отдельным шагом.
