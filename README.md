# sarykov.ru — дневник Данила Сарыкова

Статический сайт на GitHub Pages. Записи приезжают из Telegram-канала
[@danilka2028k](https://t.me/danilka2028k) сами, каждые 15 минут.

Эта страница — карта для того, кто правит код: где что лежит, что можно менять
свободно, а что сломает сайт у читателей на слабом интернете.

Помощнику, который пришёл сюда что-то поправить, хватит короткой инструкции —
[AGENTS.md](AGENTS.md): где код, как опубликовать, чего нельзя. Здесь то же
самое, но подробно.

Исходники открыты, лицензия MIT — см. [LICENSE](LICENSE).

## Как всё устроено

```
Telegram-канал
      │  каждые 15 минут, .github/workflows/telegram-sync.yml
      ▼
scripts/fetch-telegram-posts.mjs
      │  читает публичную превью-страницу t.me/s/danilka2028k
      │  тексты  → data/posts.json
      │  медиа   → assets/posts/  (сжимает и переводит в H.264)
      ▼
index.html — читает data/posts.json в браузере и рисует ленту
```

Сервера нет, базы нет, бота нет. Всё, что видит читатель, лежит в этом
репозитории — поэтому сайт открывается и там, где Telegram заблокирован.

## Где что внутри `index.html`

Весь сайт — один файл из трёх частей: **СТИЛИ** (`<style>` в шапке),
**РАЗМЕТКА** (`<body>`) и **СКРИПТ** (в самом низу, перед `</body>`). Внутри
каждой части — заголовки-комментарии заглавными буквами, ищите по ним. Та же
карта продублирована комментарием в первых строках файла.

**Стили**:

| Блок | За что отвечает |
|---|---|
| `ТОКЕНЫ` | цвета, шрифты, отступы. **Меняя дизайн, начинайте отсюда** |
| `ШАПКА` | имя, разделы и часы в одну строку |
| `РАЗДЕЛЫ` | переключение вкладок |
| `ГЕРОЙ`, `ТЕЗИС` | первый экран главной |
| `ЛЕНТА` | рельс с датами, карточка записи, фильтры |
| `─── Кадр в ленте ───` | постер с кнопкой пуска, фото, кружочки |
| `─── Окно просмотра ───` | окно поверх страницы, кадр и панель управления |
| `─── Полный экран ───` | поведение при развороте на весь экран |
| `О ДНЕВНИКЕ`, `ВОПРОСЫ`, `КОНТАКТЫ И ПОДВАЛ` | остальные разделы |
| `ПОЯВЛЕНИЕ` | анимации при прокрутке |
| `МОБИЛЬНЫЕ` | правки под узкие экраны |

Вся палитра и ритм заданы переменными в `:root`. Смена настроения сайта — это
правка десятка значений там, а не переписывание стилей.

**Разметка** (`<body>`): пять панелей — `#tab-home`, `#tab-diary`, `#tab-about`,
`#tab-faq`, `#tab-contacts`. Каждая помечена комментарием вида `═══ ГЛАВНАЯ ═══`.

**Скрипт** — третья часть того же `index.html`, перед `</body>`. Отдельного
файла со сценарием больше нет: одна правка — один файл. В начале скрипта лежит
содержание с семью разделами, искать по их названиям.

| Функция | Что делает |
|---|---|
| `showTab` / `tabByHash` | вкладки и адреса вида `#/dnevnik` |
| `movePill` | переезжающая капсула в шапке |
| `buildTheater` | собирает окно просмотра и весь плеер: пуск, перемотка, звук |
| `showInTheater` | показывает ролик номер N: источник, пропорции, подпись |
| `sizeStage` | место под кадр: пропорции и предел увеличения |
| `pickLevel` / `nearestLevel` | какой уровень качества нужен экрану и зрителю |
| `openTheater` / `closeTheater` / `step` | открыть, закрыть, соседний ролик |
| `buildEntry` | собирает одну карточку записи |
| `renderInto` | рисует ленту, возвращает список тем |
| `renderFilters` | кнопки рубрик |
| `splitTitle` | берёт первую строку записи как заголовок |
| `partsFromDate` | дата и день недели для рельса |

**В ленте плеера нет** — только кадр с кнопкой (`buildPoster`, классы `pl__*`).
Это обычная картинка-постер: ни одного элемента `<video>` на странице, ни байта
ролика по сети до нажатия.

**Всё управление — в окне просмотра** (`openTheater`, классы `tv__*`). Нажатие
на кадр открывает его: крупный кадр, дорожка с перемоткой, скорость, громкость,
качество, полный экран, стрелки к соседним роликам.

**Плеер свой, не библиотека.** Пробовали Plyr 3.8.4 — вернулись обратно.
Готовая библиотека стоит 32 КБ, тянет своё оформление поверх нашего и приносит
свои болячки (в той версии сломан установщик пропорций, а в круглом кадре её
панель не помещалась по хорде). Наш плеер — двести строк, и каждая делает то,
что нужно этому сайту.

Что в нём есть и почему это важно — каждый пункт закрывает поломку, которая
здесь уже случалась:

* **пропорции ставятся до чтения файла** (`--tv-ratio` из данных записи).
  Иначе видео до метаданных занимает 300×150 и окно на глазах прыгает. Когда
  файл открылся, его настоящий размер уточняет пропорцию;
* **на узком экране дорожка уходит на свою строку.** В одном ряду с восемью
  кнопками ей оставалось десять точек, перематывать было нечем;
* **скорость переустанавливается при каждой смене файла.** Браузер по
  стандарту сбрасывает `playbackRate` при загрузке источника, и кнопка
  показывала «2×» у ролика, который шёл на обычной скорости;
* **отпускание ползунка слушается на всём окне.** Палец уходит за пределы
  полоски, и ползунок раньше залипал;
* **пока тянут ползунок, кадр его не двигает** — иначе он дёргался назад;
* **нажатия по кадру слушает сцена, а не видеоэлемент.** На паузе кадр закрыт
  большой кнопкой пуска, и до видео нажатие не доходило — двойной тап для
  перемотки не работал;
* **ролик вытаскивается сам, когда связь рвётся.** Через VPN, гостиничный
  вайфай или в метро соединение подвисает посреди файла, и браузер об этом
  молчит: ни ошибки, ни движения — просто вечное колечко. Плеер следит за
  тем, растёт ли закачанное, и если за семь секунд не прибавилось ни доли
  секунды, идёт по лесенке: тот же файл заново с того же места → ступень
  качества вниз → ещё ступень → и только тогда сдаётся. Каждый шаг подписан,
  чтобы человек понимал, ждать ему или уходить. Автоматический спуск не
  запоминается: это вынужденная мера, а не выбор зрителя;
* **обрыв связи отличается от битого файла.** Браузер и там, и там ставит код
  «формат не поддержан» — при обрыве просто потому, что не успел прочитать ни
  байта. Различаем по тому, пришло ли хоть что-нибудь: если нет, пробуем
  снова, если да — файл действительно не тот, и перезапрашивать бессмысленно;
* **есть сообщение об ошибке** со ссылкой на файл и кнопкой «попробовать
  снова». Раньше не открывшийся ролик показывал чёрный прямоугольник без
  объяснений;
* **колечко ожидания** видно и во время игры. Раньше о задержке говорила
  мигающая кнопка пуска, которая при игре спрятана;
* **окно модальное по-настоящему:** Tab не уходит за него, страница под ним
  помечена `aria-hidden`;
* **громкость и скорость помнятся** между заходами (`localStorage`);
* **ползунок громкости показывается только там, где есть мышь.** На телефоне
  громкость на кнопках корпуса, а iOS свойство `volume` вообще не слушает;
* **закрытие окна выпускает из полного экрана.** Иначе браузер оставался
  развёрнутым на уже спрятанном окне: страница видна, а выйти можно было
  только кнопкой браузера или свайпом. В полном экране первый Esc сворачивает,
  и только второй закрывает окно — иначе одно нажатие теряло место в ролике.

**Три качества, версия выбирается сама.** Сборщик делает к каждому ролику
две версии поменьше — среднюю `-mid.mp4` (1280) и лёгкую `-low.mp4` (640) — и
пишет в данные размер кадра и вес каждого файла. Основная версия — какая
пришла из Telegram, вплоть до Full HD: раньше её обрезали до 1280 мы сами,
строкой `scale='min(1280,iw)'` в сборщике. Средний уровень появился вместе с
Full HD — без него телефону пришлось бы выбирать между мылом в 360p и файлом
вдвое тяжелее того, что его экран способен показать.

`pickLevel` считает, сколько настоящих точек займёт кадр (геометрия
окна, а не текущая разметка — в момент выбора кадр ещё не разложен), плотность
экрана ограничивает двойкой и берёт лёгкую версию, если та покрывает четыре
пятых нужного. На телефоне это лёгкая, на мониторе — полная. Вручную качество меняется кнопкой в панели
(она показывает настоящее разрешение — `512p`, `720p`), место и состояние
воспроизведения при этом сохраняются; при 2G и экономии трафика всегда лёгкая.

Выше исходника подняться нельзя: кружочки Telegram отдаёт 512×512, и «Full HD
кружочек» — бессмыслица. У обычного видео потолок теперь 1920: что пришло, то
и лежит. Растянуть 720p до 1080p нельзя — детали от этого не появится,
появится только вес. Поэтому кадр не растягивается больше чем в 1,6 раза от размера файла
(`--tv-cap`) — детали от этого не прибавится, а мыла прибавится. Если лёгкая версия не вышла
легче на 15 процентов, она не сохраняется: смысла в ней нет. Поэтому у ролика,
пришедшего в 720p, уровней будет два, а не три, а у кружочка — два.

**Полный экран** держит на себе библиотека, включая обходной путь для iPhone,
где система разворачивает только сам видеоэлемент. Нам остаётся кружочек: в
полном экране он должен остаться кругом и не раздуться выше настоящего размера
файла — за это отвечает блок `─── Полный экран ───` в стилях.

Окно одно на всю страницу, у него один плеер — меняется только источник.
Клавиши: пробел или K — пуск, ← → — пять секунд, ↑ ↓ — громкость,
Home и End — начало и конец, M — звук, F — полный экран, N и P — соседний
ролик, Esc — закрыть. На дорожке, когда она в фокусе, работают ещё PageUp и
PageDown — минута вперёд и назад.

На телефоне: одиночный тап по кадру — пуск и пауза, двойной тап по левой или
правой половине — пять секунд назад или вперёд.

Второй набор кнопок прямо в ленте был убран сознательно: он повторял окно и
стоил около 170 строк кода и четырнадцати элементов `<video>` на странице.

## Как опубликовать

```sh
git pull                       # над сайтом работает не один помощник
# ... правки в index.html ...
node scripts/check-site.mjs    # проверка перед публикацией
git add -A && git commit -m "что сделано"
git push origin main
```

Через минуту GitHub Pages выкладывает изменения на https://www.sarykov.ru сам.

**Правку видно не сразу.** GitHub Pages отдаёт страницу с
`Cache-Control: max-age=600`, поэтому у того, кто уже заходил, браузер до
десяти минут показывает старую копию — и не спрашивает сервер вовсе. Замер:
при заблокированном служебном работнике повторный заход не доходит до сервера
ни одним запросом. Заголовок задаёт хостинг, поменять его нельзя.

Отсюда правило проверки: **увидев старое поведение после выкладки, сначала
обновите страницу с очисткой** — Ctrl+Shift+R на компьютере, на телефоне
закрыть вкладку и открыть заново. Иначе легко «найти» баг, который уже
починен. Служебный работник берёт страницу мимо этого кэша
(`fetch(..., { cache: 'no-store' })`), так что у постоянных читателей задержка
меньше, но полагаться на это при проверке не стоит.

`scripts/check-site.mjs` ловит то, что уже ломалось хотя бы раз: ссылку на
чужой сервер, путь к несуществующему файлу, синтаксическую ошибку в скрипте,
пропавший раздел или окно просмотра, `<video>` вернувшийся в ленту, битые
ссылки в записях. Пишет по-русски и говорит, что чинить. Та же проверка идёт
сама на GitHub при каждой отправке — `.github/workflows/proverka.yml`; красный
крестик у коммита означает, что у читателей сайт уже сломан.

Добавили новую важную вещь — допишите на неё проверку, иначе следующий
помощник снесёт её и никто не заметит.

## Что нельзя ломать

Это не вкусовщина — каждый пункт куплен замерами на канале 400 кбит/с,
то есть на том интернете, который есть у части читателей.

**1. Шрифты только свои, из `assets/fonts/`.**
Не возвращайте `<link>` на `fonts.googleapis.com`. Пока внешний сервер молчит,
страница стоит белой: замер показал **13,4 секунды до появления текста против
1,3 секунды со своими шрифтами**. В регионах этот домен режут.
Описания `@font-face` встроены прямо в `index.html` между метками
`/* ШРИФТЫ:НАЧАЛО */` и `/* ШРИФТЫ:КОНЕЦ */` — отдельный файл стоил бы лишнего
обращения к серверу. **Руками между метками не писать**: блок перезаписывает
`node scripts/vendor-fonts.mjs`, он же кладёт woff2 и обновляет `fonts.css`.

**2. Плеер свой, библиотеку сюда не тянуть.**
Ни `cdn.plyr.io`, ни Video.js, ни что-либо ещё с чужого сервера: такие адреса
режут там же, где Google, а подпись `integrity` с неверным хэшем блокирует
файл вообще везде. Plyr уже пробовали и убрали — 32 КБ, чужое оформление и
свои поломки. Всё, что нужно, у плеера уже есть; список его особенностей выше,
там же написано, какую поломку каждая из них закрывает.

**3. Шрифты подключаются после ленты.**
Блок `<style id="fontStyles" media="print">` не даёт браузеру качать 174 КБ
начертаний, пока не приедут записи; скрипт страницы переключает `media` на
`all` сразу после отрисовки. Замер: первая запись появляется через **3,8 секунды
вместо 7,4**. Не убирайте `media="print"` и вызовы `enableFonts()`.

**4. Сайт живёт в одном файле — так и оставьте.**
Стили, разметка и скрипт лежат в `index.html`. Это сделано затем, чтобы правка
внешнего вида или поведения была правкой одного файла, а не поисков по репози-
торию. Замер показал, что на канале 400 кбит/с это ничего не стоит: текст
появляется через те же ~2 секунды, объём загрузки тот же. Разносить обратно по
файлам не нужно.

**5. Служебный работник `sw.js` — не удалять.**
Благодаря ему повторный заход не тратит **ни одного байта**, а при полном
обрыве сети сайт всё равно открывается со всеми записями. Страницу и
`posts.json` он берёт из сети (кэш только на случай обрыва), статику — из кэша,
видео не трогает вовсе. Меняете список файлов — поднимите `CACHE` на новую
версию, иначе у читателей останется старый кэш.

**6. Экономный режим.**
При 2G или включённой экономии трафика на `<html>` вешается класс `thin`:
отключаются фоновая подсветка, размытия и постеры к видео. Проверять — в
DevTools через Network throttling и `navigator.connection`.

**7. Ноль байт видео до нажатия.**
В ленте нет ни одного элемента `<video>` — только картинка-постер с кнопкой.
Сам плеер и файл появляются после нажатия. Не возвращайте `<video>` в карточки
и не ставьте `preload="metadata"`: браузер полезет в файлы сам, и открытие
страницы будет стоить мегабайтов.

**8. Медиа не трогать руками.**
`assets/posts/` и `data/posts.json` перезаписывает робот. Любая ручная правка
пропадёт при следующей синхронизации.

**9. Пять разделов остаются разделами.**
Вкладки `Главная · Записи · О дневнике · Вопросы · Контакты` в одну строку с
именем — это просьба владельца сайта. Не сводите их обратно к одной длинной
странице.

**10. Экраны — от 320 пикселей до телевизора.**
Проверено на ширинах 320, 360, 390, 430, 768, 1024, 1280, 1440, 1920, 2560 и
3840. Выше 1600 пикселей растут и полоса, и кегль, и рельс: на телевизоре,
который смотрят с трёх метров, колонка в 1160 пикселей с текстом 19 пикселей
нечитаема. Горизонтальной прокрутки не должно быть нигде.

**11. Пульт и клавиатура.**
На телевизорах и приставках курсора нет — ходят стрелками. Рамка выбора
(`:focus-visible`) обязана быть заметной, а `scroll-margin-top` не даёт липкой
шапке накрыть выбранный элемент. Мелкие ссылки расширены невидимой подложкой
до размера, в который попадают пальцем и пультом, — не убирайте `::after`
у `.entry__more` и `.foot a.u`.

**12. Читается без Telegram.**
Тексты, фото и видео обязаны лежать на самом сайте. Ссылка «Оригинал» — это
дополнение, а не способ доставки.

## Как проверять правки

Первым делом — проверка, она бесплатная и находит большинство поломок:

```bash
node scripts/check-site.mjs
```

Дальше глазами. Сборки нет, сайт открывается как есть:

```bash
python3 -m http.server 8000    # затем http://localhost:8000
```

Проверить руками:

- открываются все пять разделов, в том числе по прямой ссылке (`/#/dnevnik`);
- в ленте есть записи, фильтры переключаются;
- кружочек играет по нажатию и встаёт на паузу повторным;
- на ширине 390 пикселей нет горизонтальной прокрутки;
- в консоли пусто;
- при загрузке страницы не качается ни одного `.mp4`.

Сборщик можно погонять и вручную — но помните, что он перезапишет `data/`
и `assets/posts/`:

```bash
node scripts/fetch-telegram-posts.mjs
```

Без `ffmpeg` он отработает, но молча пропустит сжатие: в логе будет строка
`Обработка медиа: ffmpeg НЕТ`. В GitHub Actions ffmpeg ставится отдельным шагом.
